# nekcode-gui：与 nek CLI 的功能对照清单

目标：桌面端（本机与 Remote SSH）能使用 nek CLI 的全部功能。每一项写明来源、负责阶段和验证方式。

- **来源**：nek 侧路径相对 `G:/coding/nekcode/packages/coding-agent/src/`；`/xxx` 为 nek 斜杠命令；`rpc:` 为 RPC 命令或事件（`docs/rpc-commands.md`）。
- **阶段**：对应计划 `.nek/plans/nekcode-gui_facb09.plan.md` §12 的 P0–P8。
- **验证**：`T:<文件>` 单元测试（路径必须是实际存在的测试文件）；`E:<场景>` 已执行的打包 Electron E2E；`R:<场景>` SSH Docker 远程 E2E（本机未执行）；`M:<步骤>` 人工验收（本轮未执行的人工步骤明确标注）。
- 状态：`[x]` 已实现并验证；`[~]` 已实现但仍有接线或验证缺口；`[ ]` 未实现；`[-]` 不做（写明原因）。

## 0. 当前实现快照（2026-11-01 核查）

- **打包验收已覆盖本机主链路**：已有记录显示 Windows 打包应用 + nek 开发版 + 本地 OpenAI 兼容 mock 运行 `scripts/acceptance/packaged-e2e.mjs` 01–10 全部通过；该记录沿用，不是本次会话重跑。断言范围是：01–04 引导与工作区、05 全部 13 个设置页及一次 `settings.json` 写入、06 首发/项目信任/`ls` 工具行、07 用量指示、08 ask_question（单选与 Other）、switch_mode 审批、plan_review 执行及 `2/2` todo、09 重启恢复历史会话且侧栏只列已使用会话、10 停止运行中的生成。下列只把这些步骤覆盖到的行为写成 `E:packaged-e2e/<step>`，不把截图或未断言的旁观结果当作证据。
